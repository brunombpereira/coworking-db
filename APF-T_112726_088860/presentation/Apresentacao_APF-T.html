O que resolve?

Sistema completo de gestão para um operador de coworking com múltiplos espaços físicos - do registo de cliente ao pagamento, com auditoria e regras de negócio.

Domínio principal

  • Clientes, planos (Flex / Fixo / Privado) e adesões
  • Reservar salas de reunião à hora
  • Reservar postos ao dia ou via adesão
  • Pagamentos com snapshot do preço cobrado

Operações transversais

  • Notificações automáticas via triggers
  • Lista de espera + promoção a reserva
  • Reservas recorrentes (semanais)
  • Auditoria temporal (history tables)
Stack: SQL Server 2019 Express · C# WinForms (.NET 8) · ADO.NET parametrizado · zero SQL injection por construção

Supertype recurso

SQL_DDL.sql · linhas 90-115 
CREATE TABLE recurso (
    recurso_id INTEGER IDENTITY(1,1) PRIMARY KEY,
    tipo       NVARCHAR(10) NOT NULL
        CHECK (tipo IN ('Sala','Posto'))
);

CREATE TABLE sala (
    recurso_id  INTEGER PRIMARY KEY
                REFERENCES recurso(recurso_id) ON DELETE CASCADE,
    espaco_id   INTEGER NOT NULL REFERENCES espaco(espaco_id),
    nome        NVARCHAR(100) NOT NULL,
    capacidade  INTEGER NOT NULL CHECK (capacidade > 0),
    preco_hora  DECIMAL(10,2) NOT NULL CHECK (preco_hora > 0),
    CONSTRAINT uq_sala_espaco_nome UNIQUE (espaco_id, nome)
);
Supertype com PK = FK ao recurso + CASCADE delete. Uma única FK em reserva.recurso_id cobre salas e postos.

03Implementação · UDF

fn_recurso_disponivel

User_defined_functions.sql 
CREATE FUNCTION fn_recurso_disponivel (
    @recurso_id INTEGER, @data_reserva DATE,
    @hora_inicio TIME, @hora_fim TIME
)
RETURNS BIT
AS
BEGIN
    IF EXISTS (
        SELECT 1 FROM reserva r
        WHERE r.recurso_id   = @recurso_id
          AND r.data_reserva = @data_reserva
          AND r.estado <> 'Cancelada'
          AND ( @hora_inicio < r.hora_fim
                AND @hora_fim > r.hora_inicio )
    )
        RETURN 0;     -- ocupado
    RETURN 1;         -- disponível
END;
Usada pela aplicação antes de oferecer a opção de reservar, e pelo trigger T7 antes de aceitar o INSERT.

03Implementação · Stored Procedure

sp_criar_reserva_sala

Stored_procedures.sql · concorrência com sp_getapplock 
CREATE PROCEDURE sp_criar_reserva_sala
    @cliente_id INTEGER, @recurso_id INTEGER,
    @data_reserva DATE, @hora_inicio TIME, @hora_fim TIME, ...
AS BEGIN
    SET XACT_ABORT ON;
    DECLARE @lock_res NVARCHAR(255) =
        CONCAT('reserva_recurso_', @recurso_id, '_', @data_reserva);

    BEGIN TRANSACTION;

    EXEC sp_getapplock                          -- evita race condition T1
         @Resource  = @lock_res,
         @LockMode  = 'Exclusive',
         @LockOwner = 'Transaction';

    INSERT INTO reserva (...) VALUES (...);    -- dispara T1, T2, T3, T7, T12

    COMMIT;
END;
sp_getapplock em modo Exclusive · Transaction serializa INSERTs concorrentes para o mesmo recurso/dia. Resolve a race condition que existiria com apenas o trigger T1.

03Implementação · View

vw_top_clientes_receita

Views.sql · ranking de clientes com RANK() 
CREATE VIEW vw_top_clientes_receita AS
SELECT
    c.cliente_id,
    c.nome,
    COALESCE(SUM(pg.valor), 0)                            AS receita,
    COUNT(pg.pagamento_id)                                AS num_pagamentos,
    RANK() OVER (ORDER BY COALESCE(SUM(pg.valor),0) DESC) AS posicao
FROM cliente c
LEFT JOIN pagamento pg
       ON pg.cliente_id = c.cliente_id
      AND pg.estado = 'Pago'
GROUP BY c.cliente_id, c.nome;
Usada no UC Estatísticas para ranking. RANK() em vez de ROW_NUMBER() permite empates correctos. LEFT JOIN garante que clientes sem pagamentos aparecem com receita = 0.

03Implementação · Trigger T6

Snapshot do preço cobrado

Resposta directa à pergunta "qual o preço?" no pagamento

Triggers.sql · trg_pagamento_valor_correto 
CREATE TRIGGER trg_pagamento_valor_correto
ON pagamento AFTER INSERT, UPDATE AS
BEGIN
    IF EXISTS (
        SELECT 1 FROM inserted i
        JOIN reserva r ON i.reserva_id = r.reserva_id
        WHERE i.preco_servico_snapshot <> r.valor )
    BEGIN
        ROLLBACK;
        THROW 50005, 'Snapshot não corresponde ao valor da reserva.', 1;
    END
    -- (idem para adesão)
END;
preco_servico_snapshot + CHECK constraint + este trigger garantem que o valor cobrado fica imutável mesmo que o preço do serviço mude depois - 3 níveis de defesa.

Filtered indexes

Indexes.sql · optimizações chave 
-- Reserva: detecção de sobreposições (T1) por recurso/dia
CREATE INDEX idx_reserva_recurso
    ON reserva (recurso_id, data_reserva, hora_inicio, hora_fim);

-- Pagamentos: filtered indexes evitam linhas NULL (~50% storage)
CREATE INDEX idx_pagamento_adesao
    ON pagamento (adesao_id)
    WHERE adesao_id IS NOT NULL;

CREATE INDEX idx_pagamento_reserva
    ON pagamento (reserva_id)
    WHERE reserva_id IS NOT NULL;
SET STATISTICS IO ON confirma: T1 sobreposição passa de Table Scan → Index Seek. Filtered indexes em pagamento reduzem ~50% storage porque metade das linhas tem o ID a NULL.

ALTER TABLE adesao    SET (SYSTEM_VERSIONING = ON);
ALTER TABLE reserva   SET (SYSTEM_VERSIONING = ON);
ALTER TABLE pagamento SET (SYSTEM_VERSIONING = ON);

-- Reconstituir estado num instante passado:
SELECT *
FROM   reserva
FOR    SYSTEM_TIME AS OF '2026-05-01 00:00:00';
Cada UPDATE/DELETE escreve a versão anterior em <tabela>_history automaticamente. Sem trigger adicional, sem schema manual de histórico. Suporta FOR SYSTEM_TIME ALL / AS OF / BETWEEN.
